# Deploying to GitHub Pages with Minified Assets

Deploying a React, Vite, and Babylon.js 3D game to GitHub Pages requires specific considerations for **subdirectory base paths**, **dynamic static assets**, and **minified production builds**.

Follow this guide to configure the project so that production builds run perfectly on GitHub Pages (e.g., `https://<username>.github.io/<repo-name>/`).

---

## Key Challenges & Solutions

### 1. Subdirectory Base Path (Vite Config)
* **The Problem**: GitHub Pages serves applications from a subfolder (`/<repo-name>/`). By default, Vite builds use an absolute base path (`"/"`), which causes resources (JavaScript, CSS, and models) to fail to load with `404 Not Found` errors.
* **The Solution**: Configure Vite to use a relative base path (`"./"`), which automatically adapts to any subdirectory or root path environment.

#### Recommended `vite.config.ts` Change:
```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import tailwindcss from '@tailwindcss/vite';
import path from 'path';

export default defineConfig(() => {
  return {
    base: './', // Ensures relative assets resolve correctly on GitHub Pages subpaths
    plugins: [react(), tailwindcss()],
    resolve: {
      alias: {
        '@': path.resolve(__dirname, '.'),
      },
    },
    server: {
      hmr: process.env.DISABLE_HMR !== 'true',
      watch: process.env.DISABLE_HMR === 'true' ? null : {},
    },
  };
});
```

### 2. Static Asset Loading (Models & Textures)
* **The Problem**: In the codebase, 3D models (`.glb`) and textures (`.png`) are referenced dynamically via absolute strings, e.g., `/src/assets/Models/` and `/src/assets/Textures/`. 
  1. Vite's production bundler only bundles files that are statically imported (`import ... from '...'`). Un-imported assets in `/src/assets/` are excluded from the output `dist/` folder.
  2. Absolute paths like `"/src/assets/..."` attempt to read from the root domain, ignoring the subfolder.
* **The Solution**: 
  1. Create a root `public` directory and move static assets inside it. Files inside the `public` directory are copied as-is directly to the root of the `dist/` production folder.
  2. Update the asset loading paths in your code to use **relative paths** (`"./assets/..."`).

#### Step-by-Step Asset Migration:
1. Create a `public` directory in the project root:
   ```bash
   mkdir -p public/assets
   ```
2. Move (or copy) your static files from `/src/assets/Models/` and `/src/assets/Textures/` to the public folder:
   * `/src/assets/Models/` $\rightarrow$ `/public/assets/Models/`
   * `/src/assets/Textures/` $\rightarrow$ `/public/assets/Textures/`

3. Update the loading path in **`/src/player/Car.ts`**:
   ```typescript
   // FROM absolute dev paths:
   SceneLoader.ImportMeshAsync("", "/src/assets/Models/", "car_1.glb", scene)
   const carTexture = new Texture("/src/assets/Textures/Car Texture 1.png", scene, false, false);

   // TO relative public paths:
   SceneLoader.ImportMeshAsync("", "./assets/Models/", "car_1.glb", scene)
   const carTexture = new Texture("./assets/Textures/Car Texture 1.png", scene, false, false);
   ```

4. Update the loading path in **`/src/ai/PoliceCar.ts`**:
   ```typescript
   // FROM absolute dev paths:
   SceneLoader.ImportMeshAsync("", "/src/assets/Models/", "car_2.glb", scene)
   const carTexture = new Texture("/src/assets/Textures/Car Texture 2.png", scene, false, false);

   // TO relative public paths:
   SceneLoader.ImportMeshAsync("", "./assets/Models/", "car_2.glb", scene)
   const carTexture = new Texture("./assets/Textures/Car Texture 2.png", scene, false, false);
   ```

### 3. Automated Deployment Workflow (CI/CD)
To automate the production build and deployment, create a GitHub Actions workflow inside `.github/workflows/deploy.yml` that triggers on every push to your main branch.

Create a new file `.github/workflows/deploy.yml`:
```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches:
      - main # Change this to master if your default branch is master

permissions:
  contents: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 18
          cache: 'npm'

      - name: Install Dependencies
        run: npm ci

      - name: Build Application
        run: npm run build

      - name: Deploy to GitHub Pages
        uses: JamesIves/github-pages-deploy-action@v4
        with:
          folder: dist # The output folder generated by 'npm run build'
          branch: gh-pages # The branch to deploy compiled static assets to
```

Once the GitHub Action completes:
1. Go to your repository settings on GitHub.
2. Under **Pages**, ensure the Source is set to **Deploy from a branch** and the branch is set to `gh-pages` (root folder).
